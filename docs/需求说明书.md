## 1. 项目概述

### 1.1 背景

用户希望对本地任意 `.exe` 可执行程序进行访问控制：在未输入正确密码前，程序不得启动。加密操作应通过系统右键菜单便捷触发；密码由工具统一管理；卸载工具后，所有曾被加密的程序应恢复为可直接双击运行的普通可执行文件。

### 1.2 产品定位

AppEncrypt 是一款 **Windows 桌面端第三方软件加密工具**，面向个人用户及小型团队，提供对单个可执行文件的轻量级密码保护能力。产品强调 **易用性**（右键即可加密）、**可逆性**（卸载即失效）与 **本地存储**（不依赖云端）。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 宿主程序 | 用户选中的原始 `.exe` 文件 |
| 启动器（Stub） | 加密后替换宿主程序名称的轻量可执行文件，负责密码校验与解密启动 |
| 密文包 | 宿主程序经加密后生成的数据文件，与启动器配对存在 |
| 加密记录 | SQLite 中一条与宿主路径、哈希、盐值等相关的元数据 |
| 工具根目录 | AppEncrypt 安装目录，存放程序本体、SQLite 数据库及配置 |

### 1.4 设计原则

- **最小侵入**：不修改 Windows 系统核心组件；右键菜单通过标准 Shell 扩展或注册表实现。
- **可完全撤销**：卸载时必须能还原全部已加密程序，不遗留无法运行的“僵尸 exe”。
- **本地优先**：密码与元数据默认仅存本机，不上传云端。
- **安全基线**：数据库中不存储明文密码，仅存密码验证所需材料（见 4.3 节）。

## 2. 用户角色与使用场景

### 2.1 用户角色

| 角色 | 描述 |
|------|------|
| 普通用户 | 安装工具，对自有 exe 加密/解密，日常使用 |
| 管理员 | 安装/卸载工具；卸载时触发全局解密（与普通用户合并为同一安装实例） |

### 2.2 典型场景

**场景 A — 加密程序**

1. 用户在资源管理器中右键某个 `MyApp.exe`
2. 选择「使用 AppEncrypt 加密」
3. 弹出密码输入对话框（含确认密码）
4. 加密成功，提示完成；此后双击该 exe 需输入密码

**场景 B — 正常使用已加密程序**

1. 用户双击已加密的 `MyApp.exe`（实际为启动器）
2. 弹出密码输入框
3. 密码正确 → 宿主程序在受控环境下启动，用户无感知差异
4. 密码错误 → 提示错误，进程终止，宿主不启动

**场景 C — 卸载工具**

1. 用户通过「设置 → 应用」或安装包卸载 AppEncrypt
2. 卸载程序读取 SQLite 中全部加密记录
3. 对每条记录：删除启动器与密文包，将解密后的原始 exe 写回原路径
4. 卸载 Shell 扩展、清理注册表与数据库
5. 用户再次双击原路径 exe，可直接运行

## 3. 功能需求

### 3.1 安装与注册

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-01 | 提供标准 Windows 安装包（MSI 或 Inno Setup / NSIS 等），支持自定义安装路径 | P0 |
| FR-02 | 安装时注册资源管理器右键菜单项：「使用 AppEncrypt 加密」 | P0 |
| FR-03 | 右键菜单仅对 `.exe` 文件显示（单选文件；多选时禁用或提示） | P0 |
| FR-04 | 安装时创建工具根目录下的 SQLite 数据库文件（如 `appencrypt.db`） | P0 |
| FR-05 | 安装时注册卸载程序，卸载入口可被系统「应用和功能」识别 | P0 |
| FR-06 | 若未安装工具，已加密 exe 不应处于“半可用”状态（见 3.6 异常处理） | P1 |

### 3.2 加密流程

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-10 | 用户右键 exe → 选择加密 → 弹出模态对话框输入密码 | P0 |
| FR-11 | 密码输入框支持显示/隐藏密码；需二次确认密码，两次不一致则拒绝加密 | P0 |
| FR-12 | 密码强度策略（初版）：最小长度 6 位，允许字母数字及常用符号；空密码禁止 | P0 |
| FR-13 | 对同一 exe 重复加密时：若已加密，提示「该程序已加密」并提供「更改密码」或「取消」 | P1 |
| FR-14 | 加密过程：生成随机盐值与文件标识；使用用户密码派生密钥；对宿主 exe 全文加密生成密文包 | P0 |
| FR-15 | 加密完成后：在原路径用启动器替换原 exe 文件名；密文包存于约定位置（见 5.2） | P0 |
| FR-16 | 在 SQLite 写入加密记录：原始路径、文件大小、修改时间、盐值、密码哈希、密文包路径、加密算法版本、创建时间等 | P0 |
| FR-17 | 加密失败时（磁盘空间不足、文件被占用、权限不足）回滚，保证原 exe 不被破坏 | P0 |
| FR-18 | 加密成功后可选：创建原文件备份至用户指定目录或 `%AppData%\AppEncrypt\backup`（默认关闭） | P2 |

**推荐加密技术参数（初版）**

- 密钥派生：PBKDF2-HMAC-SHA256，迭代次数 ≥ 100,000
- 对称加密：AES-256-GCM（含认证标签，防篡改）
- 密码存储：仅存 `salt + password_verifier`（如派生密钥的 HMAC 或 Argon2id 哈希），**不存明文密码**

### 3.3 启动与密码验证

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-20 | 双击已加密 exe 时，由启动器拦截执行，弹出密码对话框（与应用 UI 风格一致） | P0 |
| FR-21 | 从 SQLite 按 exe 路径或内嵌文件 ID 读取对应加密记录 | P0 |
| FR-22 | 用户输入密码后，本地验证；验证失败显示「密码错误」并退出，**不得**启动宿主进程 | P0 |
| FR-23 | 连续验证失败次数限制（如 5 次 / 5 分钟），超限后锁定该次启动尝试 | P1 |
| FR-24 | 验证通过后：解密密文包至临时目录或内存映射，启动宿主进程并等待其退出；退出后清理临时明文 | P0 |
| FR-25 | 启动器与宿主进程生命周期：宿主异常崩溃时仍应清理临时解密文件 | P0 |
| FR-26 | 支持带命令行参数的启动：`MyApp.exe --foo bar` 应原样传递给宿主 | P1 |
| FR-27 | 支持宿主程序所在目录为当前工作目录（避免相对路径资源加载失败） | P0 |
| FR-28 | 若 SQLite 中无对应记录或密文包缺失，提示「加密数据损坏或未安装 AppEncrypt」，拒绝启动 | P0 |

### 3.4 密码与数据管理

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-30 | 所有加密记录与用户密码验证材料存储于 `{InstallDir}\appencrypt.db` | P0 |
| FR-31 | 提供「更改密码」能力：对已加密 exe 右键「更改 AppEncrypt 密码」，需验证旧密码 | P1 |
| FR-32 | 提供「解除加密」能力：右键「使用 AppEncrypt 解密」，验证密码后还原为原始 exe，并删除 SQLite 记录 | P1 |
| FR-33 | 数据库访问需防止并发损坏（SQLite WAL + 应用层文件锁） | P1 |
| FR-34 | 安装目录数据库仅本机可读；可选支持 Windows DPAPI 对数据库或敏感列再加密 | P2 |

### 3.5 卸载与全局失效

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-40 | 卸载时 **必须** 遍历 SQLite 全部 `status=active` 的加密记录 | P0 |
| FR-41 | 对每条记录：使用记录中的密钥材料解密密文包，将原始 exe 写回原路径，删除启动器（若与密文分离则一并清理） | P0 |
| FR-42 | 卸载完成后：用户双击原 exe 可直接运行，**无需**输入密码 | P0 |
| FR-43 | 单条记录解密失败时：卸载程序记录错误日志，弹窗汇总失败列表，并提供「打开日志」；其余文件继续处理 | P0 |
| FR-44 | 卸载时移除右键菜单注册、停止后台服务（如有）、删除 `{InstallDir}`（保留用户可选的 backup 目录需询问） | P0 |
| FR-45 | 卸载前若存在正在运行的已加密宿主进程，提示用户关闭后重试 | P1 |

### 3.6 异常与边界

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-50 | 加密时 exe 正在运行 → 提示关闭程序后重试 | P0 |
| FR-51 | 加密系统目录或受 UAC 保护路径下 exe → 提示需管理员权限 | P1 |
| FR-52 | 用户手动删除密文包或 db 记录 → 启动器无法启动并给出明确修复指引（重装工具无法恢复，除非有备份） | P1 |
| FR-53 | 用户复制已加密 exe 到其他路径 → 行为需在实现中明确定义（推荐：复制后无法启动，因路径与 db 绑定；或密文内嵌 ID 支持便携，列为扩展） | P1 |
| FR-54 | 工具被强制删除（非标准卸载）→ 已加密 exe 无法启动；提供独立「恢复工具」或文档说明（扩展或 P2） | P2 |

## 4. 非功能需求

### 4.1 性能

| 编号 | 需求描述 |
|------|----------|
| NFR-01 | 启动器冷启动至弹出密码框 ≤ 2 秒（SSD 环境） |
| NFR-02 | 50 MB 以内 exe 加密耗时 ≤ 10 秒（普通 PC） |
| NFR-03 | 密码验证 + 解密启动（100 MB exe）≤ 5 秒 |

### 4.2 安全

| 编号 | 需求描述 |
|------|----------|
| NFR-10 | 明文密码仅存在于内存，对话框关闭即清零 |
| NFR-11 | 临时解密文件目录需设置适当 ACL，仅当前用户可读 |
| NFR-12 | 密文包应含完整性校验（GCM Tag 或 HMAC） |
| NFR-13 | 防止通过简单重命名启动器绕过（路径校验 + 内嵌签名块） |
| NFR-14 | 不在日志中记录密码或密钥材料 |

### 4.3 可用性与兼容

| 编号 | 需求描述 |
|------|----------|
| NFR-20 | 界面语言：简体中文（初版）；架构预留 i18n |
| NFR-21 | 支持 Windows 10 1903+ / Windows 11 |
| NFR-22 | 宿主程序架构（x86/x64/ARM64）与启动器架构匹配；不匹配时加密前检测并提示 |
| NFR-23 | 安装/卸载需管理员权限（Shell 扩展注册通常需要） |

### 4.4 可维护性

| 编号 | 需求描述 |
|------|----------|
| NFR-30 | 加密算法带版本号字段，便于未来升级与迁移 |
| NFR-31 | 卸载与解密逻辑共用同一「还原宿主」模块，避免行为不一致 |
| NFR-32 | 提供本地日志 `%ProgramData%\AppEncrypt\logs`（可配置关闭） |

## 5. 技术方案概要（实现参考）

### 5.1 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                    AppEncrypt 安装包                       │
├─────────────┬──────────────┬──────────────┬─────────────┤
│ 主程序 GUI   │ Shell 扩展    │ 启动器 Stub   │ 卸载程序     │
│ (加密/改密)  │ (右键菜单)    │ (嵌入/同目录) │ (全局还原)   │
└──────┬──────┴──────┬───────┴──────┬───────┴──────┬──────┘
       │             │              │              │
       └─────────────┴──────────────┴──────────────┘
                           │
                    ┌──────▼──────┐
                    │ appencrypt.db│
                    │   (SQLite)   │
                    └─────────────┘
```

### 5.2 加密后文件布局（推荐方案）

以 `C:\Apps\MyApp.exe` 为例：

| 路径 | 说明 |
|------|------|
| `C:\Apps\MyApp.exe` | 启动器（体积小，固定或按架构编译） |
| `C:\Apps\MyApp.exe.appencrypt` | 密文包（或存于 `%ProgramData%\AppEncrypt\vault\{uuid}.enc`） |

启动器内嵌或读取：

- 文件 UUID（关联 SQLite）
- AppEncrypt 魔数与版本
- 指向密文包的相对/绝对路径

**优点**：卸载时可定位密文并还原；双击行为符合用户预期（仍是原文件名）。

### 5.3 SQLite 表结构（草案）

**表：`encrypted_files`**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | UUID |
| original_path | TEXT | 宿主原始完整路径 |
| vault_path | TEXT | 密文包路径 |
| file_size | INTEGER | 原始字节大小 |
| file_hash | TEXT | 原始文件 SHA-256 |
| salt | BLOB | 密钥派生盐 |
| password_verifier | BLOB | 密码验证器 |
| cipher_version | INTEGER | 算法版本 |
| status | TEXT | active / pending / error |
| created_at | INTEGER | Unix 时间戳 |
| updated_at | INTEGER | Unix 时间戳 |

### 5.4 右键菜单实现选项

| 方案 | 说明 |
|------|------|
| 注册表 `HKEY_CLASSES_ROOT\*\shell\` | 实现简单，调用主程序并传参 `%1` |
| COM Shell Extension | 体验更好，可动态隐藏/禁用，开发成本较高 |

初版可采用 **注册表 + 主程序 CLI**（`AppEncrypt.exe encrypt "%1"`）。

### 5.5 启动器工作流程

```
双击 MyApp.exe (Stub)
    → 解析内嵌/伴生元数据，定位 db 记录
    → 弹窗输入密码
    → PBKDF2 + 验证 password_verifier
    → 失败：退出码非 0
    → 成功：AES-GCM 解密密文 → 写入 %TEMP%\AppEncrypt\{uuid}\MyApp.exe
    → CreateProcess(宿主, 继承命令行与工作目录)
    → WaitForSingleObject → 删除临时文件
```

## 7. 验收标准

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| AC-01 | 右键加密 | 任意非系统 exe 加密后，原路径文件变为需密码启动 |
| AC-02 | 密码错误 | 连续输入错误密码，宿主进程从未出现在任务管理器 |
| AC-03 | 密码正确 | 宿主功能与加密前一致（抽样 3 类：GUI 程序、CLI 带参、依赖同目录 DLL 的程序） |
| AC-04 | 数据库存储 | 密码不以明文出现在 `appencrypt.db` 中 |
| AC-05 | 卸载还原 | 卸载后所有曾加密 exe 可直接双击运行，SQLite 与 vault 已清理 |
| AC-06 | 失败回滚 | 人为制造磁盘满，加密失败后原 exe 仍可正常运行 |
| AC-07 | 改密/解密 | 更改密码后旧密码失效；解密后恢复为原始单文件 exe |

## 8. 项目范围外（Out of Scope — 初版）

- macOS / Linux 支持
- 对非 exe 格式（MSI、BAT、LNK）的加密
- 云端账户同步或多设备共享密码
- 防截屏、防调试、虚拟机检测等高级反逆向
- 对整个文件夹批量打包加密（可作为扩展）

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 杀毒软件误报启动器 | 用户无法使用 | 代码签名证书；提交 WHQL/厂商白名单 |
| 大体积 exe 解密慢 | 体验差 | 流式解密 + 进度条；可选仅加密代码段（高级版） |
| 非标准卸载导致数据残留 | 程序无法打开 | 提供独立 Recovery 工具；加密前可选备份 |
| 路径绑定导致 exe 移动后失效 | 用户困惑 | 文档说明；扩展「重新绑定」功能 |
| SQLite 与密文被篡改 | 安全/可用性 | GCM 认证 + 校验失败拒绝启动 |
